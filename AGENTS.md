# WDT maintainer context

Before investigating, designing, implementing, refactoring, or auditing any WDT-specific behavior in this repository, read `Development~/WDT/CONTEXT.md` in full.

Do not infer current branch, HEAD, release, PR, or validation state from the maintainer context. Verify current state from Git/GitHub and the active conversation handoff.

The source code is the implementation source of truth. `Development~/WDT/CONTEXT.md` records accepted design intent, invariants, responsibility boundaries, regression-sensitive behavior, and rejected alternatives that are not reliably recoverable from code alone.

When code, current Git state, handoff state, and the maintainer context appear inconsistent, investigate the discrepancy instead of silently choosing one source.
